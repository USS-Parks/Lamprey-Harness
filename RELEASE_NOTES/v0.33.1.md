# Lamprey v0.33.1 — macOS install fix

The v0.32.0 and v0.33.0 DMGs shipped an app bundle whose code seal was broken during packaging (CI skips signing, and repacking invalidates Electron's upstream ad-hoc seal). On a quarantined download macOS refuses such an app with "Lamprey is damaged and can't be opened" and offers no bypass — reported by users as a corrupt DMG.

## What changed

- The build now ad-hoc re-signs the macOS app bundle (and verifies the signature) before the DMG is created. First launch uses the normal unidentified-developer flow: right-click → Open → Open, or approve under System Settings → Privacy & Security.
- Nothing else. Application content is identical to v0.33.0 apart from the version number.

## Verified against the corruption reports

All four v0.33.0 installers were byte-verified before this fix was made: the Windows EXE matches the `latest.yml` sha512, the ZIP content listing matches v0.32.0's, the DMG and AppImage containers are structurally valid, and the CDN mirror is hash-identical to GitHub. The files were never corrupt; the DMG failure was the broken code seal above. The ~15 MB size drop from v0.32.0 is retired launcher icons no longer bundled by the renderer build.

## Still true

- Builds are ad-hoc signed only — no Developer ID certificate, no notarization, unsigned Windows binaries. SmartScreen and Gatekeeper prompts remain expected.
- There is no iOS package. The Apple artifact is a macOS DMG (Apple Silicon).
- Auto-update follows GitHub.
