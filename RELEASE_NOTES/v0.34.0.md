# Lamprey v0.34.0 — Workspace world model

Lamprey now understands the workspace it is editing. Before any tool call changes a file, it is checked against what is actually on disk, and the checks run outside the model, so a small local model gets them for free.

This is the GAVEL paper (arXiv:2609.19315) built into a coding harness. The paper's result: a deterministic model of the world, placed between the language model and execution, took a compact 8B model from 41% to 92% task success and let it beat much larger models used alone. The target here is the same for open-weight models like Qwen and DeepSeek — finish long-horizon coding work without a frontier-sized model behind it.

## What it does

- **Verify.** Every workspace-changing tool call is checked against the live filesystem first. For a patch, each hunk is replayed against the current bytes, so the exact "did not apply at hunk N" failure is caught and explained *before* the call runs, not after it half-applies.
- **Repair.** A wrong path separator, a filename that resolves to exactly one real file, or a hunk that matches except for indentation is corrected on the spot and executed, with no extra model call.
- **Batch rollforward.** A group of edits is simulated together on a shared view of the workspace, so a plan that contradicts itself (delete a file, then edit it) is rejected before anything on disk changes.
- **Follow-through.** In the default mode, the goals of a coding request are extracted, tracked in Plans & goals, and drive continued work until they are met or a ceiling stops it. Unmet goals stay visible with the evidence of what was still failing.
- **Controls.** Settings → Advanced → World model: a four-way mode (`off` / `verify` / `repair` / `full`) and budgets. An After-action World-model panel counts verdicts, repairs, and goal outcomes. On by default; `off` restores the previous dispatch exactly.

It adds **zero bytes to the model's prompt** — the intelligence is in deterministic code the model never sees.

## Evidence

The mechanism is proven end to end: a behavioral smoke drives the real dispatch pipeline against a real workspace and shows, on actual files, verify blocking a doomed edit (nothing written), repair re-anchoring a whitespace mismatch and applying it, wrong paths corrected and applied, a self-contradicting batch left entirely unexecuted, and goals flipping from unmet to met after the edit. The full test suite is 3493 passing across 15 world-model test files.

The one number not yet in hand is the *size* of the live speedup on a local Qwen or DeepSeek run. That measurement needs a keyed or local-model machine — the pass margins are fixed in advance in `PLANNING/WM_SMOKE_PLAYBOOK.md`, and the result goes in `PLANNING/WM_AFTER.md` when it runs. This release ships a proven mechanism; the magnitude of the win is the owner's to measure and publish.
