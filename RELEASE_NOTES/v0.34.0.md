# Lamprey v0.34.0 — Workspace world model

Before a tool call changes anything, Lamprey now checks it against what actually exists in the workspace. A patch whose target has moved, or whose surrounding lines have drifted, comes back with the reason instead of failing blindly. A mechanical mistake — a wrong path separator, a filename that resolves to exactly one real file, a hunk that matches except for whitespace — is corrected without spending a model turn. A batch of edits that would contradict itself is caught before any of it runs. And in the default mode the turn keeps working until the goals of a coding request are actually met, rather than stopping at the model's first "done."

This is a translation of the GAVEL paper (arXiv:2609.19315) into a coding harness. The paper's finding is that a deterministic model of the world, sitting between the language model and execution, recovers most of what expensive models buy — its compact 8B model went from 41% to 92% single-task success, and beat much larger models run without the world model. The aim here is the same for open-weight models like Qwen: finish long-horizon coding work reliably without a frontier-sized model behind it.

## What changed

- **Verify.** Every workspace-mutating tool call is checked against the live filesystem before it runs. The `apply_patch` check replays each hunk against the current bytes and predicts the exact "did not apply at hunk N" failure in advance.
- **Repair.** Path-separator, unique-filename, and whitespace-only patch mismatches are fixed deterministically, with no extra model call.
- **Batch rollforward.** A group of edits is simulated together, so a plan that dooms its own later step is rejected before anything on disk changes.
- **Follow-through.** In `full` mode, the goals of a coding request are extracted, tracked in Plans & goals, and drive continued work until met or a ceiling stops it; unmet goals are left visible with the evidence of what was still failing.
- **Controls.** New Settings → Advanced → World model tab with a four-way mode (`off` / `verify` / `repair` / `full`) and budgets. An After-action World-model panel counts verdicts, repairs, and goal outcomes. Ships on by default; set it to `off` to dispatch tool calls with no checks, exactly as before.

It adds **zero bytes to the model's prompt** — the checks live entirely outside the model. That is the point: a cheap model gains this reliability without being lectured into it.

## Honest limits

- The **live benchmark numbers are not measured yet.** The mechanism and its 163 unit tests pass, and the pass margins are written down in advance (`PLANNING/WM_SMOKE_PLAYBOOK.md`), but the size of the real gain on Qwen-via-Ollama is an owner-machine measurement that has not been run. This release ships the mechanism, not a proven speedup.
- The workspace bench is a representative floor (ten tasks across rename / guard / create / delete / config / nested-edit / append / multi-part shapes), extensible in `bench/wm/tasks.ts`.

## Still true

- Builds are ad-hoc signed only — no Developer ID certificate, no notarization, unsigned Windows binaries. SmartScreen and Gatekeeper prompts remain expected.
- There is no iOS package. The Apple artifact is a macOS DMG (Apple Silicon).
- Auto-update follows GitHub.
